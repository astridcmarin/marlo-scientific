# Owner review of AI-assisted extractions

Written 31 October 2026.

## Why

Every extract on the platform is labelled "AI-assisted, independent review pending". The platform's main claim is that every number traces back to a source, and that claim currently rests on unreviewed extractions. This workflow lets the platform owner check the values that matter against the original documents and records the result, so the label can change.

## What is reviewed

`intelligence_store/data/extraction_review_queue_v1.json` (pinned in `extraction_review.py`) lists **166 values**: every value that feeds a calculation or a quoted dose. The file is generated by `scripts/build_extraction_review_queue.py` from the pinned extracts.

**Priority 1:**
- Hughes 2019 parameters and variability;
- Kim 2026 parameters;
- the CC-5013-PK-001 renal groups (the 25 mg reference and the outside checks);
- the lenalidomide exposure–safety odds ratios;
- the REVLIMID label doses and Table 3;
- the ixazomib Gupta 2017 parameters;
- the pomalidomide and dexamethasone label values.

**Priority 2:** the daratumumab Luo 2021 parameters (outside checks only; not run on any page).

**Not listed:** values the platform derives itself, such as the average daily dose of an every-other-day regimen, and uncertainty statistics such as RSEs and bootstrap intervals.

Each item gives the value, the file and JSON pointer, the location in the source, and where to look. The page refuses to load if any listed file has changed or any value no longer matches.

## How

1. Open `/models/extraction-review` (linked from `/models`).
2. For each value choose **Matches**, **Wrong** (with a note on what the source shows) or **Can't check**. The draft is kept in the browser.
3. Download the review record and run `flask extraction-review-check FILE`. This validates the record against the queue and prints its checksum.
4. Pin the record: add it to `intelligence_store/data/` and to `REVIEW_RECORDS` in `extraction_review.py` with its checksum. The page then shows each value's status.

A value found wrong is corrected by a new version of its extract, with a new pin and new checks where it feeds a result. It is never edited in place.

## What it does not do

- A review by the platform owner is not independent of the platform. Records name the reviewer, and pages will say "reviewed by the platform owner", not "independently verified".
- The review checks transcription only: whether the value is what the source says. It does not check whether the source is right or whether the model is applicable.

## Round 1 (reviewed 3 November 2026, pinned 4 November)

Record `intelligence_store/data/extraction_review_record_2026-11-03_v1.json`, reviewer Astrid, pinned unchanged in `REVIEW_RECORDS`. 165 of 166 values reviewed: **143 matches, 12 wrong, 10 can't check**; one not reviewed (pomalidomide with ketoconazole alone, AUC 1.19-fold). The page shows these decisions as recorded.

**Reading of the 12 marked wrong** (the reviewer noted that some were marked as a precaution because the queue showed values in a different form from the source). In each case the reviewer's note is the source's own figure, and the extract stores the same figure as a fold change, as the extract's quote shows:

| Item (pomalidomide label) | Source says | Stored | Reviewer's note |
|---|---|---|---|
| Severe renal, on dialysis | AUC increased 38% | 1.38 | 0.38 |
| ESRD, non-dialysis days | increased 40% | 1.40 | 0.40 |
| Child-Pugh A / B / C | increased 51% / 58% / 72% | 1.51 / 1.58 / 1.72 | 0.51 / 0.58 / 0.72 |
| Fluvoxamine, 90% CI | 98% to 157% increase | 1.98–2.57 | 98% to 157% |
| Fluvoxamine + ketoconazole | 146% [126% to 167%] | 2.46 [2.26–2.67] | 146%; 126% to 167% |
| Carbamazepine | decreased 20% [13% to 27%] | 0.80 [0.73–0.87] | 20%; 13% to 27% |
| Smoking | AUC decreased 32%; Cmax increased 14% | 0.68; 1.14 | 32%; 14% |

So no extract is corrected and no new extract version is made. The queue was at fault: it showed a converted number without the source's wording.

**Can't check (10):**
- Ixazomib lag time: Gupta's Table 3 gives the log-scale estimate (−1.52, the reviewer's note) and states 13 min; the extract stores 13 min as 0.2167 h. exp(−1.52) = 0.219 h, the same value at the table's rounding.
- Dexamethasone high-fat meal AUC: the label says the meal "had no effect on AUCinf" (the reviewer's note); stored as 1.0-fold.
- Pomalidomide: moderate or severe renal impairment not on dialysis ("not significantly affected", stored as 1.0); high-fat meal ("decreased mean plasma Cmax and AUC by about 27% and 8%", stored as 0.73 and 0.92).
- REVLIMID Table 3: three dose cells and two CLcr bounds. The bounds are the "below 30" rows, stored as a range with no lower end, so the queue showed only "30" under an index label.

**Next: round 2.** A queue v2 should show, next to each converted value, the source's own words and the conversion ("label: increased 38%; stored as 1.38-fold"), label range ends in words ("upper end of CLcr range, < 30 mL/min"), and re-list the 23 items not marked matches. A round 2 record would then supersede these items' status. Until then the page shows them as recorded in round 1.
